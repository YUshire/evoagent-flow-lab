## 为什么自进化被拒绝

首轮本地自动候选与基线评分同为 0.8071。输入主要是重复运行失败和已接受的集成反馈，没有针对原评测误报的有效学习信号。生成了多个结构化字段，但最初只有 prompt_additions 被应用，few-shot 内容未进入实际评测。

新编写的上下文实验包括 18 条受控样本（6 train / 6 validation / 6 holdout）；候选只根据 PR #1 中已核对的错误分类反馈生成，不接收验证/隐藏集标签。训练样本仅归档，没有用于调参。原提示词和候选各运行 6 条验证与 6 条隐藏样本，共 24 次真实模型 replay。

第一次上下文实验的适配器格式说明不明确，出现 confidence 字符串及缺失 findings 的问题。记录保留在 contextual-evolution/，不用于声称模型效果。修正 JSON 协议后，在 contextual-evolution-v2/ 独立复测：

| 指标 | 基线 | 候选 |
|---|---:|---:|
| 验证评分 | 1.0 | 1.0 |
| 验证 F1 | 1.0 | 1.0 |
| 隐藏集评分 | 1.0 | 0.82 |
| 隐藏集 F1 | 1.0 | 0.8 |

候选没有达到 +0.01 的验证提升要求，并使隐藏集出现退步，因此判定 rejected；没有降低阈值或强行激活。这个小样本结果说明门槛阻止了候选退步，不能作为大规模生产精度估计。

## 演化机制的正向证明

controlled-activation/ 用新编写的 12 条受控数据验证确定性 PromptPolicyReviewer：确认漏报 → 自动生成 focus-rule 提示词版本 → 验证提升 → 隐藏集不退步 → 激活 → 回滚原版本。

验证 F1：0.5 → 1.0；隐藏 F1：0.5 → 1.0。激活决策为 activated，回滚验证通过。

这证明配置/策略演化会改变审查行为且能通过门槛；它不是外部 LLM 权重训练，也不是实际模型精度提升的证据。此前四方案各 100 条真实模型合成样本对照仍作为历史证据保留。
